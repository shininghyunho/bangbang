# Git Commit Architect

이 스킬은 프로젝트의 변경 사항을 추적 가능하고 읽기 쉬운 형태로 기록하기 위한 **Git 커밋 표준 지침**을 제공합니다.

## 📋 핵심 원칙

1. **논리적 원자성 (Atomic Commits)**:
    - 하나의 커밋은 하나의 논리적인 변경 단위만 포함해야 한다.
    - 대규모 변경 사항은 여러 개의 작은 커밋으로 분할하여 기록한다.

2. **커밋 메시지 구조 (Header & Body)**:
    - **Header**: `type: what` 형식으로 작성하며, 무엇이 바뀌었는지 영문 또는 한글로 간략하게 기술한다. (예: `feat: add kakao login`, `refactor: optimize search query`)
    - **Body**: 무엇을 **"왜"** 바꾸었는지를 중심으로 **한글**로 기술한다. 너무 장황하지 않게 핵심만 가독성 있게 작성한다.

3. **가독성 및 일관성**:
    - 지난 커밋 메시지의 스타일을 참고하여 프로젝트의 일관성을 유지한다.
    - `- [상세항목]` 형식을 활용하여 변경된 세부 사항을 명확히 리스트업한다.

## 🛠 작성 가이드

### 커밋 메시지 템플릿

```text
type: 요약된 변경 내용 (What)

- [대상] 변경된 이유와 배경 설명 (Why) - 한글 작성
- [대상] 세부 변경 사항 1
- [대상] 세부 변경 사항 2
```

### 타입(Type) 관례
- `feat`: 새로운 기능 추가
- `fix`: 버그 수정
- `refactor`: 코드 리팩토링 (기능 변경 없음)
- `docs`: 문서 수정
- `infra`: 인프라 및 설정 변경
- `test`: 테스트 코드 추가 및 수정

## 🚀 실행 프로세스

1. `git status`로 변경 사항을 확인한다.
2. 변경 사항을 논리적 단위로 그룹화한다.
3. 각 그룹에 대해 `git add` 후, 본 스킬의 원칙에 따라 메시지를 작성하고 `commit`한다.
