# [ADR-001] 재귀 CTE를 활용한 400만 건 대용량 시드 데이터 생성 전략

## 1. Summary
- **결정**: 외부 스크립트(JS) 및 CSV 파일 의존성을 제거하고, 재귀 CTE(Recursive Common Table Expression)를 활용한 단일 SQL 문으로 400만 건의 시드 데이터 생성 환경 구축
- **날짜**: 2026-04-29

## 2. Context (배경)
- **문제 상황**: 
  - 대용량 검색 성능 테스트를 위해 400만 건 이상의 데이터가 반복적으로 필요함. 
  - 기존에는 JS 스크립트로 CSV를 생성한 후 `LOAD DATA`로 삽입했으나, 파일 I/O 대기 시간이 길고 외부 런타임 환경(Node.js)에 의존적인 문제 발생.
- **요구 사항 및 제약**: 별도의 도구 설치 없이 DB 클라이언트만 접속 가능한 환경에서도 즉시 동일한 규모의 테스트 데이터를 재현할 수 있어야 함.

## 3. Alternatives (대안 목록)
- **대안 A**: 외부 스크립트(Node.js) + CSV Bulk Load
  - 별도 언어 런타임 및 파일 시스템 쓰기 권한 필요.
  - 데이터 생성(Script) -> 저장(CSV) -> 로드(DB)의 3단계 공정으로 인한 비효율.
- **대안 B (선택)**: 재귀 CTE 기반 단일 SQL 생성
  - 별도 인프라 의존성 없이 순수 SQL만으로 데이터 정의 및 삽입 가능.
  - 선언적(Declarative) 코드로 데이터 생성 규칙 가독성 확보.

| 비교 항목 | 대안 A (JS + CSV) | 대안 B (SQL CTE - 선택) |
| :--- | :--- | :--- |
| **환경 의존성** | 언어 런타임, 파일 시스템 필요 | **DB 엔진만으로 실행 가능** |
| **처리 단계** | 3단계 (파일 I/O 포함) | **1단계 (In-memory 생성)** |
| **재현 편의성** | 낮음 (스크립트 공유 필요) | **높음 (SQL 문 공유)** |

## 4. Decision (결정)
- **결론**: **재귀 CTE 및 Cross Join을 활용한 SQL 기반 생성 방식 채택**
- **근거**: 
  - 프로젝트 환경이 Docker 등으로 격리될 때 외부 의존성을 최소화하여 개발자 경험(DX)을 개선.
  - 메모리 내에서 즉시 데이터를 생성함으로써 불필요한 디스크 I/O를 제거하여 데이터 준비 시간을 획기적으로 단축함.

## 5. Trade-offs (Pros/Cons)
- **Pros (얻은 것)**
  - **성능 대폭 향상**: 기존 방식(약 5분) 대비 생성 및 삽입 시간(약 30초)을 90% 이상 단축함.
  - **환경 독립성**: SQL 파일 하나만으로 별도의 런타임 설정 없이 대용량 테스트 환경 구축 가능.
  - **유지보수 용이**: 데이터 생성 규칙 변경 시 SQL 코드 수정만으로 즉시 반영됨.
- **Cons (포기한 것)**
  - **엔진 설정 의존**: `max_recursion_depth`와 같은 DB 시스템 변수 조절이 선행되어야 함.
  - **문법적 제약**: 매우 복잡한 랜덤 데이터 생성 시 프로그래밍 언어(JS) 대비 SQL 표현력의 한계가 존재함.

## 6. Retrospective (회고)
- **성과**: 재귀 CTE의 한계(재귀 깊이 제한)를 극복하기 위해 `Cross Join` 기법을 설계에 도입한 결과, 400만 건의 데이터를 생성하면서도 실제 재귀 횟수는 수천 번 수준으로 유지하여 시스템 부하를 최소화하며 성공적으로 데이터를 구축함.
- **한계 및 보완**: 현재는 단일 실행 파일에 모든 생성 로직이 포함되어 있어 데이터 규모가 더 커질 경우 트랜잭션 로그(Undo Log) 비대화 문제가 우려됨. 향후 대규모 데이터 삽입 시에는 데이터를 청크(Chunk) 단위로 분할하여 삽입하는 전략을 검토할 예정임.
